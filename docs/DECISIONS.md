# Decisions

Dated 2026-10-13. Technical choices below are provisional engineering defaults for Phase 1. They are not farm policy. Section 18 of `docs/blueprint.md` is still unanswered; do not treat a schema choice as the owner's answer.

## Answered for Phase 1 (technical)

| Id | Decision | Why |
|---|---|---|
| T1 | Monorepo npm workspaces: `@gavran/shared`, `@gavran/server`, `@gavran/client`. | One schema package for API and UI validation. |
| T2 | MySQL 8.4 in Docker. The host port is `MYSQL_PORT` and `DB_PORT`. `.env.example` uses 3317. App user `gavran`. Local passwords live in `docker-compose.yml` and `.env.example` and are not production secrets. Automated tests and CI set `DB_PORT` to 3307. | 3317 avoids a host MySQL on 3306 and Cursor forwarding on 3307 on the owner's Windows PC. |
| T3 | Browser auth uses httpOnly cookies `gavran_access` (JWT, 15 minutes) and `gavran_refresh` (14 days, rotated). CSRF is a non-httpOnly `gavran_csrf` cookie matched to `X-CSRF-Token`. Tokens are not returned as access or refresh fields in JSON. Locale may be stored in `localStorage` under `gavran.locale`. | Blueprint authentication note: do not store long-lived credentials in localStorage. |
| T4 | Passwords use Node `scrypt` with N=16384, r=8, p=1, keyLen=64. Format `scrypt$N$r$p$salt$hash`. This is the Node interactive default and still needs a security review before production. | No extra password library. |
| T5 | A user with zero memberships, or an existing owner, may create a farm and becomes its owner. Invited workers cannot create a farm. | Stops shadow farms without blocking the first owner. |
| T6 | Family helpers receive no role permissions. Extra access is an explicit per-membership grant. System administrator is `users.platform_role`, not a farm role, and has no business permissions. There is no UI to grant that platform role. | Deny by default. |
| T7 | Phase 1 permission keys are only `farm.read`, `farm.update`, `shed.read`, `shed.create`, `shed.update`, `user.read`, `user.manage`, `audit.read`. | No settings or finance API exists yet. |
| T8 | Provisional role matrix is in `docs/PERMISSIONS.md` and `shared/src/permissions.ts`. Manager may create and update sheds. Owner confirmation is still required. | Blueprint WF-01 says the owner creates sheds; the manager row says managers work with sheds. |
| T9 | Shed type allowlist: brooder, grower, layer, breeder, quarantine, storage, other. Capacity unit is the literal `birds`, integer 0 through 1,000,000. Default timezone `Asia/Kolkata`. Weight `kg` or `g`. Volume `L` or `mL`. | Structural lists only. They do not set stocking, temperature, medicine, price, or tax rules. |
| T10 | Invitation attaches the person immediately. No email or SMS is sent. Linking an existing email does not change that password. | No delivery provider in Phase 1. |
| T11 | Deactivate sets user status, revokes sessions, and keeps memberships. The last active owner cannot be removed or deactivated. | Reactivation restores the previous role. History stays. |
| T12 | Audit summaries pass through a redactor for keys matching password, token, secret, authorization, or cookie. Login success and failure are account-scoped (`farm_id` null) and do not appear on the farm activity page. | Blueprint audit requirements. |
| T13 | `Idempotency-Key` (8–80 printable ASCII) is optional on farm create, shed create, and member invite. | Retries can replay the stored response. |
| T14 | DDL is not wrapped in a transaction. A failed migration file can leave partial tables. Down scripts exist. | MySQL implicit commit on DDL. |
| T15 | `LIMIT` and `OFFSET` are interpolated only after they are validated integers, because mysql2 prepared statements reject those placeholders. | Documented in the audit repository. |
| T16 | The dev client port is `CLIENT_PORT`. `.env.example` uses 5317 and proxies `/api` to `PORT` 5318 so cookies stay same-origin. | 5317 and 5318 stay off 3000, 5173, and 8080, and off 4317 and 4318, which Cursor already forwards on the owner's Windows PC. |
| T17 | Canonical Git history remote is https://github.com/UrveshMore/gavran-poultry-farm-system on `main`. | Owner request, 2026-10-13. |
| T18 | Bird types are names the farm types. Batch status is only `open` or `closed`. Movement types are opening, transfer, sale, mortality, culling, and other exit. A sale has no price field. | Decision 3 is still open, so no species catalog was seeded. |
| T19 | Egg sorts are names the farm types. Fertile and table are optional labels the screen can create; they are not required rows. A collection may omit batch and shed. Counts are whole eggs. There is no price column. | Owner answer on 2026-10-13, decision 2. |
| T20 | Incubator temperature and humidity have no default and no set-point. A reading may omit both. A number requires the unit the farm types. Service status is `in_service` or `out_of_service`. | Decision 5 leaves incubation SOPs unanswered. |
| T21 | An incubation sitting is `incubator` or `broody_hen`. No expected hatch date is stored or calculated. Candling has no schedule. Outcome labels are typed on the record. | Decision 4 and decision 5 are still open. |
| T22 | The hatch figure shown in the app is `live chicks ÷ eggs set × 100` and is labelled proposed. It is not decision 4. | Decision 4 is still open. |
| T23 | Tasks are created by a person. Summer heat, monsoon, and winter templates start with zero steps. No task is generated from batch age. Completion is online only, and a second completion is refused. Proof is a note when the creator asks for one. Photos and offline queues are not in this phase. | Blueprint WF-08 steps 1, 6, and 7 need farm rules this build does not invent. |
| T24 | Stock on hand is the sum of in and out quantities. A typed amount on a receipt is stored and is not a valuation. Reorder level, item unit, target age, and target weight exist only when the farm types them. Water is a note. A laboratory result is stored only as text the farm types. FCR is not calculated. | Decisions 4 and 7 are still open. FIFO, FEFO, and expiry blocking are not assumed. |
| T25 | The disease base is one row per page of the three Patil PDFs. The stored text is the PDF text layer. Marathi vowel signs in that layer are incomplete, so doses are not reconstructed. Use requires an owner or vet note and an approval flag. There is no withdrawal column. Biosecurity copies only the step-by-step PDF, and the copy starts unapproved. | Decision 5 is still open. The text layer is not a verified prescription. |
| T26 | A loss incident stores the note and count the farm types. It may link only to a mortality movement. No predator list is seeded. No mortality rate is calculated. | Decision 4 is still open. |
| T27 | Market prices and order line prices exist only when someone types them. The price list starts empty. Order status is only `draft`. `POST /invoices` returns 409 until decision 8. There is no tax column. | Decision 8 is still open. |
| T28 | An expense or income row stores the amount and money unit the farm types. Categories start empty. A correction is a new row with `reverses_entry_id`. The earlier row is not edited or deleted. No profit is calculated and no tax column exists. | Decision 9 is still open. |
| T29 | A report is a date range plus the source rows. Egg counts are a sum of those rows. The hatch figure stays the proposed ratio from Phase 6. Mortality stays uncalculated. Expense sums are per money unit and are not a profit. Feed conversion is absent. | Decisions 4 and 9 are still open. |
| T30 | The restore drill is allowed only on `gavran_restore_drill`. RPO, RTO, backup schedule, off-site copy, and retention are null or `not_chosen`. | Decisions 12 and 15 are still open. |
| T31 | A range area is a named place, not a shed, and has no capacity. Strain is optional text on a bird type. Rooster and hen counts are stored as typed integers and returned as those two numbers. | Decision 3 stays open. No breed list and no recommended ratio. |
| T32 | Attendance stores a method label the farm types. The response count is a row count. Training stores a version label the farm types. A task link blocks completion until that person has a completion row. There is no score and no course catalog. | Blueprint WF-16. No performance formula was chosen. |
| T33 | Parentage stores typed sire and dam text and optional batch ids on the same farm. `pairing.status` is `unset`. | Decision 3 stays open. No coefficient. |
| T34 | Supplier orders stay `draft`. A line price is null unless an amount and a money unit are typed. Receipts do not insert stock rows. Bills and payments are separate tables. `stockPosting` is `disabled`. Valuation stays `not_chosen`. | Decisions 7 and 8 stay open. No tax column. |
| T35 | Invoice documents use status `unposted` only. `POST /invoices` stays 409. A return row references the document and does not delete it. `balance.status` is `not_calculated`. | Decision 8 stays open. No tax column. |
| T36 | Report filters are optional shed, batch, and category ids. A section without that column is left on the date range, except hatch, loss, expense, movement, egg, and parentage rows, which narrow when the column exists. Export is the same payload. | Decisions 4 and 9 stay open. |
| T37 | Notices are rows for one farm member. `delivery` is `in_app`. `urgent.status` is `not_chosen`. | Decision 14 stays open. |
| T38 | Farm files stay on local disk under `uploads/`. Kind is taken from magic bytes: JPEG, PNG, WebP, or PDF, at most 5 MB. `scan.status` is `not_claimed`. There is no delete. | Decision 15 stays open. |
| T39 | Install uses the browser prompt, or a share-menu note on iPhone. `/api` stays `NetworkOnly`. | No offline record cache. |
| T40 | The device queue accepts only `POST .../attendance`. Stock, expenses, invoices, orders, market prices, losses, medicine, and supplier money return `refused` and are not stored. Replay uses the same idempotency key. Status 409 becomes `conflict` and is not written again. | Decision 10 stays open. |
| T41 | `document.documentElement.lang` follows `gavran.locale`. Hindi and Marathi strings are provisional. The screen says a fluent review is still needed. | No fluent review is claimed. |
| T42 | Search uses `LIKE ? ESCAPE '!'` on the current farm. The pattern escapes `!`, `%`, and `_`. Sections run only when the caller has that read permission. Amount columns are not selected. | Workers must not see prices. |
| T43 | A named report stores the name, note, and date the farm types. `cadence.status` is `not_chosen`. A run calls the existing report with `from` and `to` typed at that moment. `delivery` is `not_sent`. | No clock and no outbound message. |
| T44 | Knowledge rows are one disease, medicine, or care note. Columns are use, signs, how the paper said to give it, when, and care. Photo slides store the name and say the amount was not on the page. Unreadable brooding temperatures are not stored. Old fragment rows, and approvals or medicine rows that pointed at them, were removed. | The PDF text layer dropped vowel signs. Doses are not invented. |
| T45 | The farm home is ten tiles. Screens the role cannot open are hidden. Setup holds sheds, papers, saved count names, the spare-copy check, and the change list. A first visit starts a driver.js tour per role. Help replays it. Each screen's guide says what it is, where it is, why it is used, and how to use it. | A worker should not hunt through money screens. |
| T46 | A yard note is `let_out`, `shut_in`, or `note`, with an optional clock time. No time is suggested. Workers may write one. It is not queued offline. | A backyard day starts and ends at the gate. Decision 10 stays open. |
| T48 | `npm run db:seed:demo` is local only and throws if `NODE_ENV` is `production`. It writes one farm, code `DEMO`, and marks every row Sample. The demo owner password `admin@123` is shorter than the 10-character sign-up rule and is hashed only by this command. Sign-up, password change, and invites still use the 10-character rule. | T49 | Chick-day lines are rows copied from `patil-poultry-step-by-step-process.pdf` pages 17–27. The hatch date is paper day 1. Home still shows age as days since hatch. | T50 | **Tell me on this phone** always shows a sentence. Notices use `Notification` on a secure page, or an active service worker when one is registered. Decision 12 stays open. |
| T51 | Eggs, dose ticks, jobs, and losses may wait in IndexedDB with the same idempotency key. Attendance still keeps a 409 on the device. The Android shell stores a server address and schedules local reminders at 8:00 and 17:00 from the open dashboard. `SERVE_CLIENT` serves `client/dist` from the API only when that flag is set. | Decision 10 stays open. Decision 12 stays open. |
| T53 | Gavran Saathi drafts with the local parser first. Gemini 2.5 Flash (`gemini-2.5-flash`, temperature 0.1, JSON schema) runs only when that draft is unclear, or for a photo or a recording, and only with a key stored as AES-256-GCM under `farm_ai_keys`. The key is `sha256(JWT_SECRET)`. The API returns a hint, not the key. A draft never writes. Save calls the existing egg, loss, hatch, dose, task, stock, sale, and expense services and checks that permission again. A sick-bird answer copies `how_to_give` from `knowledge_entries` and is labelled `possible - confirm with vet`. The model is not allowed to supply a medicine or a dose. | Decision 5 stays open. Decision 13 stays open: the owner types the key before any photo leaves the computer. |
| T54 | Owner medicines are farm rows the owner or a manager types. They are labelled Added by owner. The dose sentence is only the amount, unit, route, bird count, note, and precaution they typed. Those days join the same dose list, Today's medicine, the `dose_today` alert, and Mark given, without approving the training-paper schedule. | T55 | Home charts are stored counts. Birds lost is a count, and a death rate stays unset. Income minus kharch is shown only when both numbers use the same typed unit. Sales with no unit stay on their own line. Phone alarms repeat at the minutes that person saved, default 8:00 and 17:00, and the words refresh once per farm day. A greeting is answered on the computer. A Gemini key is probed before it is stored, except while the automated tests run. | T56 | On the new-flow branch, an egg lot stores a place name, a day, and a count. A tray stores a name on one incubator. A set stores that tray, an optional lot, a set day, and a count. Each hatch day stores live chicks and, when that count is above zero, opens one Gavran flock in the chosen shed. Bad count is eggs set minus the sum of live chicks and is not clamped. The ratio is live divided by eggs set and is labelled not an official hatch percent. A bird line is died, sold, or eaten. A sale stores the amount and unit the owner typed and is added to that unit's income. Kharch quantity and rate are optional; when both are typed, the stored amount is quantity times rate. The season card is the owner's pick. The program does not map months to a season. Range, rooster and hen counts, the full movement form, the bird-type form, and the parentage menu stay in the program and are not on the menu. | Decisions 4, 5, and 9 stay open. |
| T47 | A worker or manager may be added with a name, a mobile number of 10 to 15 digits, and a PIN of 4 to 6 digits. The PIN is stored with the same scrypt hash as a password and is never returned. Five failures in the sign-in window lock that number and that address. The owner and a manager may set a new PIN, which drops that person's sessions. The owner still signs in with a mail address and a long secret phrase. Creating the person needs `user.manage`. `pin.reset` is separate, so a manager can set a new PIN without inviting people. An existing mobile number is linked and its PIN is left as it was. | No numbering plan and no delivery channel were chosen. |

## Still open (blueprint section 18)

Do not implement policy for these until the owner answers. Date the answer in this file.

1. Single farm or multiple farms? The schema allows multiple farms. That is not a business confirmation.
2. Egg categories and inventory units actually used on the farm. On 2026-10-13 the owner said eggs are sorted into fertile eggs and table eggs. Those names are optional starter labels the owner can rename or skip. Any other sort exists only after the owner adds it. Counts are eggs, not weight. No price is stored on a collection.
3. Bird types, species, strains, and batch statuses. On 2026-10-13 the owner said the flock is Desi/Gavran: indigenous, free-range or backyard. That does not seed a strain list. Strain, rooster count, and hen count stay owner-entered (see the roadmap section after P0). Batch status remains only open or closed until a further answer.
4. Official hatch-rate, mortality-rate, and FCR formulas.
5. Authoritative source documents for vaccines, medicine, feed, water, and incubation SOPs. On 2026-10-13 the owner supplied three Patil Poultry House Training PDFs, stored under `docs/sources/`, as the only extraction source for the Disease & Treatment Knowledge Base (see Phase 9 in `docs/ROADMAP.md`). That does not approve any dose. Each entry stays unverified until the owner sets its approval flag. Feed, water, and incubation SOPs are still unanswered.
6. Who can approve and publish SOP changes.
7. Stock issue and valuation methods by category.
8. When a sale or invoice is posted: order confirmation, dispatch, or delivery.
9. Accounting basis and batch-cost allocation.
10. Which workflows must work offline, and which need an online approval.
11. Devices, internet quality, language defaults, and shared phones.
12. Hosting budget, storage, AI budget, uptime, RPO, and RTO.
13. Whether external AI may process farm images.
14. Which alerts are urgent, and who receives them.
15. What must be retained, exported, anonymized, or deleted, and for how long.

`farm_settings` exists and must stay empty of invented SOP, dosage, price, or tax values. Password reset tokens are stored with no delivery endpoint.
